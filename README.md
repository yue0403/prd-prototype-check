# prd-prototype-check

一个 Claude Code Skill：核查 AI 生成的 HTML 原型与 PRD 文档之间在**功能、交互、业务规则**上是否一致。

## 背景

现在很多产品经理不再手工画原型，而是用 AI 直接生成 PRD 和 HTML 原型两份交付物给研发。因为两者是 AI 各自独立生成的，彼此之间没有一个共同的"真相来源"互相校对——PRD 可能提到了原型没做的规则，原型也可能编造了 PRD 里根本没写的功能或文案。这种不一致一旦流到研发手里，会被当作既定需求直接实现，造成返工。

这个 skill 用来在原型交付研发之前，把这类差异找出来。

## 核查范围

只核对三类内容：

- **功能**：模块/页面应具备的功能点是否都实现
- **交互**：操作反馈、状态流转、校验时机等交互细节是否一致
- **业务规则**：计算公式、边界值、权限逻辑等具体规则是否一致

视觉样式、配色、间距不在核查范围内。

## 输出

一份结构化的 Markdown 报告，按 功能/交互/业务规则 分类列出问题，标注严重程度、PRD 依据、原型现状和建议；同时单独列出原型中"PRD 未提及但被原型自行编造"的内容，以及"PRD 本身写得含糊、需要 PM 澄清"的点。报告结构见 [`assets/report-template.md`](assets/report-template.md)。

## 使用方法

1. 把这个仓库放到 Claude Code 的 skills 目录下（个人级 `~/.claude/skills/`，或项目级 `.claude/skills/`），保留 `prd-prototype-check` 这个文件夹名。
2. 在对话里提供 PRD 文档（md/txt/docx/pdf/在线文档链接均可）和 HTML 原型（本地文件、文件夹或可访问链接），说明需要核对两者是否一致，例如：

   > 帮我核对一下这份 PRD 和这个 HTML 原型有没有对不上的地方，我要发给研发了

   Claude 会自动识别场景并调用这个 skill。

## 适用场景

- 原型评审前的自查
- 发给研发前的最终核对
- PRD 与原型的验收走查
